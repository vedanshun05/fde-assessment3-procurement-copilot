# Architecture decision memo

**Decision: choose A, the single procurement agent, for a controlled pilot after live-model evaluation.** Keep B as a measured alternative rather than the default. The current artifact can be used immediately as an explicitly labelled offline demonstration; it is not approved for autonomous procurement.

Both architectures passed all six supplied public minimum checks. The expanded evaluation uses the same 32 versioned cases for A and B, with three repetitions: 96/96 runs passed per architecture. Cases cover the ten source requests, exact spend and budget boundaries, new-vendor Legal thresholds, employee PII, production integrations, 365/366-day review validity, conflicting and future vendor dates, unknown identities, missing integrations, request/registry/API prompt injection, a real vendor HTTP 503, and a controlled timeout. Both retained the required human handoff and canonical tool evidence, used five tools per run, and made zero LLM calls. Offline timings were similar and do not establish a meaningful speed difference.

These are offline simulation results. They establish coded-policy behavior and exact evidence-ledger provenance, not live language-model reasoning quality, semantic evidence entailment, adversarial robustness, production latency, or model cost. The available evidence does not justify claiming that a second reasoning stage improves outcomes.

A has one reasoning owner and a direct path from original tools to a validated recommendation. B adds an analyst assessment and a fresh reviewer context; in live mode it requires one additional structured model call after the same retrieval loop. That added handoff can help catch interpretation mistakes, but it also creates another opportunity to distort the business gap or add unnecessary reviews. Mandatory thresholds, sensitive-data rules, failure handling, and human authority are already shared deterministic controls in both systems.

Before enabling a live pilot, configure a model key locally and rerun the paired comparison with a fixed model, the same cases, and repeated attempts. Inspect rationales and source entailment manually, record ungrounded outputs and failed calls, and measure tokens, latency and false escalation. Reconsider B if it materially reduces interpretation or escalation errors enough to justify its added call and complexity. Until that evidence exists, A is the simpler implementation with no observed offline quality disadvantage. Humans retain every approval and exception decision.
